## 4. 52주 데이터 계약과 대사 작성 규칙

### 4.1 주차 엔트리 예시 (의사 코드, JSON 파일을 의무화하지 않음)

```gdscript
{
  "week": 1,
  "title": "일 년 뒤의 약속",
  "enemy_set": ["rifle"],
  "evidence_id": "E_W01",
  "evidence_source_unit_id": "rifle",
  "intro_cards": [
    {"speaker":"narrator", "text":"지구와의 연락이 끊긴 기지에 구조 메시지가 도착했다."},
    {"speaker":"noah", "text":"52주 뒤 구조선이 온대요. 발신자 정보는 없지만요."},
    {"speaker":"alex", "text":"확인 전에는 약속으로 받아들이지 마."}
  ],
  "post_win_cards": [
    {"speaker":"maya", "text":"회수한 제어기엔 온실 전력선이 최우선 표적으로 남아 있어요."},
    {"speaker":"alex", "text":"사람보다 전력선을 먼저 노렸다는 거군."}
  ],
  "next_hook": "enemy_target_priority"
}
```

- 위 W01은 **스키마 설명용 대사 예시**이며 문장 확정본이 아니다. 실제 구현 시 v9의 원문·v6 화법과 대조해 전체 52주를 완성한다.
- 각 주 `1..52` 정확히 1개, `evidence_id="E_W%02d"` 정확히 1개, `intro_cards`/`post_win_cards` 모두 1개 이상. **고정 5카드 제한 금지**; 의미 단위로 2~6장 정도에서 자유롭게 구성하되 원고의 사실을 빠뜨리지 않는다.
- 카드 필수 필드: `speaker`, `text`. 허용 화자: `narrator`, `alex`, `maya`, `noah`, `root`, `eva_record`. 한국어 표시명은 데이터 혹은 단일 매핑으로 관리한다.
- `noah`의 현재 시점 화자는 **W44부터 금지**. 과거 녹음/인용이 필요할 경우 `narrator`가 '기록'임을 명시하며 현재 대사로 보이지 않도록 한다. `eva_record`는 W50 **승리 후**부터 허용.
- 각 주 intro는 그 시점까지 이미 확정된 사실만 공개. `W43` 노아의 직접 승인, `W48` 구조 연락 합성, `W49` 구조선 미출항, `W50` 에바의 충돌 규칙, `W52` 외부 복구망 식별 충돌은 각각 **해당 주 POST_WIN** 이후만 확정.
- 구조·탐색·식당 대화는 '기지 내부 사건'으로 표시하고, 실제 전투 결과가 아닌 현장 방문을 플레이어가 했다고 말하지 않는다. 적 '귀환'·'적이 우리와 똑같이 움직임'·'적이 가짜 계획에 반응함'은 실제 로그 없이 확정 문장으로 쓰지 않는다.
- W09·W15·W19·W26·W18 및 W38~W39의 조건 문장·대체 문장은 v9 `4절`과 일치시킨다. 데이터 값이 없는 경우에는 **중립 대사**를 출력하고 좌표/기종을 창작하지 않는다.
- `enemy_set`은 **미래 스테이지 편성 제안**으로만 저장한다. UI에는 현재 시연 사각형을 실제 해당 적이라고 표시하지 않는다. 아군 주차/건물 선행조건으로 적 출현을 막지 않는다.
- 대사창 길이: 현재 `DIALOGUE_RECT=Rect2(28,778,1320,171)` 및 `FONT 28px`에서 **줄바꿈/클리핑/내부 표시 개수**를 계산해 화자와 1~3줄 대사가 겹치지 않게 한다. 문자열 전체를 한 줄로 그려 화면 밖으로 넘기는 것 금지. 기존 인풋 영역과 우측 전장은 침범하지 않는다.

### 4.2 스토리 진척과 기술트리 결합

- 기존 `owned_buildings`, `placements`, `week`, `g`가 사실의 원천이며 새로운 스토리 상태에서 이를 복제·별도 관리하지 않는다.
- '우리 전차가 공격했다'는 `placements`에 실제 전차가 있고 당시 전투 보고에 그 전차가 있었을 때만 발화. 건물을 **미보유**한 경우에는 계획·도면만 언급한다.
- 전투 시작 시 복제한 `placement_snapshot`은 전투 한 번에 대한 불변 자료여야 한다. 중도 배치 변경으로 과거를 덮어쓰지 않는다.
- W18은 W17 전투 스냅샷이 남아 있고 **동일 좌표가 증거 파일과 실제 비교되었을 때만** '전술을 따라 했다'고 표현한다. 아니면 '작전 자료가 수집된 흔적'으로 제한한다.
- W26은 해당 주 준비 시점 실제 전투 스냅샷과 적 파일의 공통 필드만 인용한다. W38~W39는 미끼 계획 A/B와 **실제 적 초기 진형 비교**가 확인될 때만 해당 추론 확정. 이 정보는 임의로 생성하거나 사용자 실배치를 미끼 계획으로 치환하지 않는다.

## 5. 전투 어댑터: 현재 미연결, 테스트에서만 주입

### 5.1 검증된 보고서의 최소 계약

```text
BattleReport {
  week: int, run_id: String, result: WIN | LOSE | DRAW,
  enemy_instance_ids_spawned: Array[String],
  enemy_instance_ids_defeated: Array[String],
  enemy_unit_id_by_instance: Dictionary,
  evidence_source_instance_id: String,
  allied_survivors: int,
  placement_snapshot: Array[Dictionary],
  optional_observations: Dictionary
}
```

- 미래 **정식 전투 시스템만** 실제 런타임에서 `accept_battle_report(report)`를 호출한다. 호출자는 `week`와 일치하고 동일 `run_id`가 미처리이며, 실제 개체 목록·사망 개체·잔여 인원을 제공해야 한다.
- `WIN` 자격: 현재 주차와 일치, 적 인스턴스 1기 이상 생성, 모든 생성된 적 인스턴스가 실제 격파 목록에 존재, `allied_survivors >= 1`, 증거 출처 개체가 생성·격파 목록에 포함되고 그 유닛 ID가 해당 주 `evidence_source_unit_id`와 정확히 일치.
- `LOSE/DRAW` 및 미확인·중복·잘못된 `run_id`·누락된 증거는 `POST_WIN`, 단서, 주차 정사 해금, 엔딩을 변경하지 않는다. 유효하지 않은 보고는 명시적 실패와 진단 로그를 반환한다.
- `optional_observations`는 실제 전투 어댑터가 제공한 필드만 읽는다. W18 경로 모방, W38~39 가짜 계획 대응 같은 증거 검증을 대신하는 상수 `true`를 게임 스토리 코드에서 넣지 않는다.
- **이번 기능에서 이 이벤트의 실제 런타임 호출부는 만들지 않는다.** `_process()`의 18초 시연 결과는 `DEMO_RESULT` 표시·보상·데모 주차 이동으로만 유지하며 정식 `BattleReport`를 생성하지 않는다.
- 테스트 `w52_story_smoke.gd`는 메모리에서 신뢰 조건을 충족/불충족하는 모의 보고서를 만들어 `story_flow.gd`의 게이트만 검증한다. 사용자 화면·공개 빌드에 테스트 전용 승리 버튼·치트 메뉴·재생산 가능한 '정사 강제 승리' 경로를 넣지 않는다.

### 5.2 데모 모드와 정사 스토리의 분리 — 필수 결정

현재 데모는 `result`에서 다음 주로 계속 이동할 수 있다. **이 기능을 유지하면서** 미실현 승리에 기반한 W02~W52 사실을 이야기로 노출하면 v9 목적에 위배된다.

- 일반 게임의 `week`/G/배치/기술트리와 **데모의 다음 주 이동**은 기존 시연 기능대로 둔다. 데모의 18초 결과 화면에는 `시연 결과 — 실제 승리 및 단서 미확정` 표시.
- **서사 진행 허가**는 W01부터 연속으로 확인된 실제 `WIN + E_Wnn`에서만 생성한다. '연속 인증된 마지막 주'는 `seen_post_win_weeks`의 연속 접두부로 계산; 데모 `week` 자체를 서사 해금의 증거로 쓰지 않는다.
- W01에서 첫 intro는 볼 수 있다. `week >= 2`이지만 해당 주 이전의 정식 승리 기록이 없으면 **현재 주 v9의 후속 사건을 보여 주지 않고**, 해당 위치에 `스토리 진행 대기 — 전투 시연만 이용 가능합니다`를 표시한다. 기존 시연 브리핑을 유지하거나 중립 안내로 대체하되 새 스토리가 진행된 것처럼 보이면 안 된다.
- 테스트/향후 정식 전투에서 정사 승리 이벤트를 정상 전달하면 그때만 현재 주의 `POST_WIN` 및 다음 주 `INTRO`가 공개된다. 선행 정사 단서가 없는 주차에 테스트용 `WIN`을 주입해도 '앞선 사건 확인'을 건너뛰지 못하도록 거부한다.
- 새 구현이 18초 결과를 호출자 한 줄만으로 정사 승리로 바꾸는 우회책은 **금지**. 일반 플레이에서 W52 엔딩 접근 가능 상태를 임의로 보장하지 않는다.
- 이 규칙 때문에 전투 미구현 상태의 실제 UI에서는 **W01 이후의 서사가 잠겨 있다.** 이는 구현 누락을 숨기는 것이 아니라 플레이·스토리 일관성을 유지하기 위해 의도적으로 보수적으로 처리한 것이다.

## 6. 상태 전이 및 저장/복원 계약

### 6.1 상태 전이

| 현재 상태 | 입력 | 다음 상태 | 단서/대사 처리 |
|---|---|---|---|
| `dialogue` (주차 도입) | Space / 대사창 클릭 | `prepare` | 가변 카드 전부 표시 후 주차 도입 읽음 저장 |
| `prepare` | 전투 시작 | `battle` | 기존 배치·G 조건 유지, 실배치 스냅샷만 확보 |
| `battle` 데모 | 18초 경과 | `result` | `DEMO_RESULT`, 기존 G 보상, **단서 0 / POST_WIN 0** |
| `result` 데모 | 다음 주 | 다음 주 `dialogue`/`prepare` | 데모 주차 변경만; v9 후속 도입은 정사 게이트 확인 |
| `battle` 정식(미구현) | 검증된 `WIN` 보고 | `post_story` | 증거 출처 확인 후 같은 주 승리 후 카드 표시 |
| `battle` 정식(미구현) | `LOSE/DRAW` 보고 | 향후 정식 결과/재도전 | 단서·에필로그·다음 주 정사 미해금 |
| `post_story` | 마지막 대사 확인 | `result` 혹은 W52 `ending` | `seen_post_win_weeks` 1회 확정; 동일 `run_id` 재접수 금지 |
| `result` 정식 | 다음 주 | 다음 주 `dialogue` | `E_Wnn` 및 이전 연속 주 완료 확인 |
| W52 `ending` | 모든 엔딩 카드 확인 | 비전투 `W53 에필로그` → 완료 | `ending_seen` 1회; 추가 전투 없음 |

- `post_story`는 v9 승리 후 대사를 위한 새 상태. `ending`은 W52 결과와 W53 에필로그의 화면 서술. `phase="result"` 하나만으로 승리 여부를 판단하지 않는다.
- 기존 W01 `dialogue_index == 3`에서 특정 노드를 선택하는 튜토리얼 부수효과는 카드 개수 변경으로 트리거가 무너지지 않게 **명시적 W01 튜토리얼 단계 ID**로 옮기거나 독립 이벤트로 유지한다. `_set_week_intro()`의 아군 배치 초기화·선택 기준과 정보창/카메라 동작은 유지한다.
- 연타/동시 클릭·키 입력에서 카드가 두 번 넘어가거나 이벤트가 이중 처리되지 않아야 한다. 한번 읽음 처리된 이벤트는 재입장/저장 복원에서도 중복 반영하지 않는다.
- 스토리 카드 스킵은 **표시만 생략**하며 승리/증거 획득을 발생시키지 않는다. 승인된 승리 후 카드를 스킵할 경우 `post_story` 확인 상태만 완료한다.

### 6.2 버전 5 저장 (현재 `save_manager.gd` v4 → v5)

기존 `session` 키 `week`, `g`, `phase`, `dialogue`, `help`, `placements`, `buildings`는 보존. 신규 내용은 일관된 단일 블록(예: `story` 섹션)으로 저장한다.

```text
story: {
  intro_seen_weeks: Array[int],
  post_win_seen_weeks: Array[int],
  evidence_flags: Array[String],           # E_W01 .. E_W52
  card_index: int,                          # 현재 phase의 다음/현재 카드 인덱스
  pending_verified_post_week: int | 0,      # 검증된 WIN 후, 카드 확인 전
  processed_run_ids: Array[String],         # 중복 승리 이벤트 방지
  previous_deployment_snapshot: Array,
  ending_seen: bool
}
```

- `SAVE_VERSION=5`로 상향하되 `load_game()`은 **기존 v2/v3/v4 및 v5**를 읽고 각 버전의 원래 배치/건물 검증과 v2·v3 배치 마이그레이션을 유지한다. v1은 여전히 거부.
- v4 이전 저장에 **실제 승리 기록은 존재하지 않으므로** 과거 `phase="result"`, `week>1`이나 G 보상값에서 서사 단서를 역산·지급하지 않는다. v2/v3/v4 저장은 유효한 게임 플레이 상태로 이어 가되 **서사 확인 플래그는 빈 상태**부터 시작한다.
- `seen_post_win_weeks`는 `1..52`의 **중복·누락 없는 연속 접두부**, `evidence_flags`는 해당 확인된 주차에만 대응. 중간 주를 빠뜨린 `post_story` 저장은 거부한다. `pending_verified_post_week`는 연속 완료 주차의 바로 다음 주이자 현재 전투 주차여야 한다.
- 저장 중 `phase="battle"`은 기존처럼 `prepare`로 복구하되, 아직 검증되지 않은 결과·증거를 생성하지 않는다. `phase="post_story"`는 검증된 `pending_verified_post_week`가 있는 경우에만 유효하며 남은 카드를 이어서 표시한다.
- W52 `ending`과 `ending_seen=true`는 W01~W52 연속 완료 및 `E_W52`를 검증해야 한다. 저장 복원 시 잘못된 값은 엔딩으로 진입시키지 않는다.
- `card_index` 범위는 해당 주·`phase` 실제 카드 개수에 맞춘다. 기존 `dialogue` 0..5 하드코딩을 v5 서사 카드 범위로 가져오지 말고, 구 저장 복원 시에는 구 데모 대사 진행값의 의미를 보존하면서 새 서사 이벤트로 오인하지 않는다.
- `placements`는 최대 12, 합법적인 `unit_id`/건물 선행조건/적군·아군 격자 제한 등 **기존 검증을 그대로 유지**. 저장 손상/부분 누락은 명시적으로 복구 거부 또는 비서사 원래 값 복구로 처리하고 침묵 속의 임의 엔딩 개방 금지.
- 상위 `main.gd`의 일시정지→메뉴 저장 호출을 우선 재사용. 원자적 저장 필요 여부는 현재 `ConfigFile.save` 방식의 실패 동작을 기준으로 확인하고, 스토리 데이터만 따로 저장하다 부분 적용되는 방식은 도입하지 않는다.

### 7.2 테스트 가능한 상태 전이 시나리오

1. `W01~W52`의 각 주에서 `DRAW`, `LOSE`, 누락된 증거 적, 격파되지 않은 증거 적, 아군 생존 0, 중복 `run_id`를 입력: **POST_WIN·다음 주 정사·엔딩 불가**.
2. `W01`부터 연속으로 실제 요건을 갖춘 `WIN`을 입력: 해당 주 승리 후 카드 1회, `E_Wnn` 1회, 다음 도입은 이전 승리 후에만 가능.
3. `W02`보다 먼저 `W03` 성공 보고를 주입: 선행 `E_W01/E_W02`가 없으므로 거부.
4. W09 공장 미보유, W15 격납고 미보유, W19 전차 미생산: 핵심 서사 정상, 강제 생산/건설 없음.
5. W18 이전 배치 로그 없음, W26 전투 배치 없음, W38~39 적 진형 비교 없음: 과장된 전술 추론 대신 중립 문구 또는 사건 잠금.
6. W43 승리 전·후, W44 격리 이후, W48·W49·W50 승리 전·후: 스포일러 게이트 및 화자 금지 확인.
7. W52 DRAW/LOSE → 엔딩 안 보임; W52 검증 WIN과 연속 52개 증거 → W53 비전투 엔딩 1회.
8. W17 도입 중 저장, W43 `post_story` 1장 읽은 뒤 저장, W52 엔딩 읽는 중 저장·복원: 카드 중복·건너뜀 없음.
9. 기존 v2/v3/v4 저장에서 `result`를 불러와도 `post_win_seen_weeks=[]`, `evidence_flags=[]`. 기존 건물·배치·주차·G 유지.
10. 데모 18초 결과 및 다음 주 이동 52회는 가능하지만 **정사 단서와 W52 엔딩은 0회**. UI에 `시연`임을 명시한다.

### 7.3 실행 정책과 종료 기준

- `AGENTS.md`: 개발 중 **정적 검증 → 원인 분석 → 최소 수정 → 관련 검사 재실행 → 설계-구현 재대조**. 발견한 불일치를 설계서 감사 기록에 남기고 확인 가능한 불일치 0건까지 반복한다.
- 공통 규약은 로컬 게임/브라우저 실행을 금지하며, `AGENTS.md` 상위 프로젝트 절은 **개발판 요청 시 GitHub Actions의 헤드리스 씬 스모크·Web Export·Pages 검증만 예외 허용**한다. 새 세션에서 무단 로컬 Godot 실행·브라우저 QA·실전 밸런스 시뮬레이션을 하지 않는다.
- 기존 `tests/w52_ui_smoke.gd`를 통과시키기 위한 임의 테스트 삭제·검증 비활성화·일방적 기능 제거 금지. 기존 검증이 새 카드 수 때문에 달라졌다면 검증의 **동일 기능 계약**을 새 구현 방식으로 정직하게 수정한다.
- 정적 대조 결과를 요구 ID (`S01..S12`), 파일·함수 위치, 판정 `일치/불일치/검증불가`와 조치로 기록한다. 수행하지 않은 헤드리스·브라우저·플레이 테스트는 `PASS`라 쓰지 않는다.
- 사용자가 **별도로 개발판 확인을 요청하면** 기능 브랜치 변경만 `devel`에 제한 반영하고 실제 Actions 빌드·게시 성공을 확인한다. `main` 병합은 **명시적인 '메인에 머지' 요청 후에만**.
- 완료 보고는 브랜치·커밋·변경 파일·52주 데이터/대사·저장 호환성·검증 명령과 결과·devel/main 미반영 상태·남은 실제 전투 인터페이스를 포함한다.

1. **루프 A — 가변 카드/저장 진행:** v5 `save_manager.gd::load_game()`가 대사 인덱스를 구 5장 기준으로 `clampi(...,0,5)` 처리하고 있었다. v5의 실제 `card_index`·대사 진행을 손실할 수 있어 **v5에는 클램프를 적용하지 않고 실제 카드 수 검증으로 전환**했다. 구 v2~v4는 데모 5장 진행값을 그대로 복원하도록 `legacy_demo_intro` 중립 카드 모드를 도입하고, 해당 데모 대사를 v9 `intro_seen`으로 오인하지 않게 했다. W01 구 시연 문구의 미실행 아군 선택 단정도 제거했다.
2. **루프 B — 상태/배치 무결성:** v5 `validate_state()`가 존재할 수 없는 phase·카드 끝 인덱스·과거 주차 이력 순서·완료 후 데모 결과를 일부 허용했고, 이전·승리 직전 스냅샷에 현재 저장된 배치와 맞지 않는 항목을 허용할 수 있었다. **연속 도입 기록, 실제 종료 상태, 인덱스 미완료 범위, 이전/대기 스냅샷과 `SaveManager`의 기존 합법 배치 검증**을 추가해 이를 거부했다. `tests/w52_story_smoke.gd`의 주차 전환 fixture에도 실제 `Game._set_week_intro()`와 같은 결과 초기화를 추가했다.
3. **루프 C — 조건부 대사 진위/보고서 검사:** W18/W26의 좌표 관측에서 병종 정보가 제공됐는데도 불일치 여부를 확인하지 않았고, W38/W39에서 불일치한 대조를 '대조 자체가 없었다'고 표현할 여지가 있었다. **공통 필드(좌표와 제공된 병종)의 일치**, 중복·음수 미끼 진형 좌표 거부, 불리언 미끼 준비 확인 및 실제 확인된 내용만 서술하는 중립 대사로 수정했다. 또한 2,048회 시도 이후 `run_id_capacity`로 모든 향후 승리를 막을 수 있는 임의 제한을 제거했다.
4. **루프 D — v5의 필수 데이터/초기 v5 호환:** v5 로딩에서 `session.dialogue`·`help`·`phase` 등의 누락이 기본값으로 조용히 대체될 가능성이 있었다. v5에 필수 키·버전 정수형·도움말 범위·대사 정수형 검증을 추가했다. 한편 이전 선구현 커밋의 초기 v5에는 새 `legacy_demo_intro` 필드가 없으므로, **오직 초기 v5의 알려진 1개 필드 차이만** 읽을 때 `false`로 보완하는 `StoryFlow.upgrade_early_v5()`를 추가했다. v2~v4의 과거 배치/건물 마이그레이션은 보존했다.
5. **루프 E — 회귀 테스트·UI 카드/서사 계약:** 이전 `w52_story_smoke.gd`가 W26/W38/W39 재검사 시 직전 주 WIN 상태를 그대로 들고 온 점을 정정하고, 검증 성공/거부 양방향 좌표 사례와 구 v4 대화 인덱스 0/1/3/4/5, 이전 초기 v5, 누락 필드, W53 **7장 중 제7카드 직전(index 6)** 복원 fixture를 추가했다. `w52_ui_smoke.gd`에는 실제 `Game.restore_state()`의 구 대화 복원 및 정사 단서 0회 확인을 추가했다. 데이터 접근자는 지원하지 않는 섹션과 비활성 대화 phase에서 후속 사건을 반환하지 않도록 제한했다.

6. **루프 F — 튜토리얼 이벤트와 테스트 전이:** W01 소총병 포커스가 원래 세 번째 카드 이벤트가 아니라 마지막 카드 종료 시에 발생했고, 주차별 시험에서는 LOSE/DRAW 직후 '재도전 준비' 상태가 아닌 기존 비승리 결과가 남아 유효한 `prepare` 복원 fixture를 깨뜨렸다. W01의 지정 카드에 `event_id=w01_rifle_focus`를 부여하고 해당 카드 확인 시 1회만 선택하도록 수정했다. 레거시 5장 브리핑의 같은 이벤트 지점도 명시했다. 전투 검증 시험은 `LOSE/DRAW→prepare`의 `last_outcome=""` 초기화를 수행하고 W01 포커스 전후 검사를 UI 계약에 추가했다.
7. **루프 G — 보고서 아군 좌표 중복:** `StoryFlow._valid_snapshot`가 아군 `instance_id`는 중복 검사했으나 서로 다른 아군 인스턴스가 동일한 격자를 차지한 경우를 허용했다. 동일 격자 `col:row`를 거부하고 각 주 승리 보고서 테스트에 중복 배치 반례를 추가했다. 원래 `SaveManager._valid_placements`의 좌표 유일성 계약과 동일해졌다.

### 11.3 최종 정적 재검사와 경계

- **현재 후속 감사 정적 대조:** 52개 WeekScene/고유 단서, 원본 v9 312항목 메타데이터 대조, 301개 기본 대사 카드, 적 12종, 화자/스포일러 게이트 **불일치 0건**.
- 수정한 `story_data.gd`, `story_flow.gd`, `game.gd`, `save_manager.gd`, `tests/w52_story_smoke.gd`, `tests/w52_ui_smoke.gd`에 대해 **문자열/괄호 균형, 함수명 중복 및 관련 참조의 정적 검사에서 문제 0건**. **이는 Godot 구문 분석기 실행이나 스크립트의 실제 통과가 아니다.**
- **후속 감사 수정·정적 재대조 그룹 7회**(루프 A~G), 최초 구현 감사의 3회와 별도 기록. 수정마다 관련 항목과 테스트 fixture를 다시 대조했으며 현재 확인 가능한 불일치는 남지 않았다.
- `AGENTS.md`의 프로젝트 검증 정책 때문에 이번 후속 감사에서는 **Godot 실행/스크립트 테스트 0회, PC·Web/브라우저 플레이 QA 0회, 빌드·배포 0회**. 따라서 `S10~S12`의 실행 판정은 계속 `미검증`이며, 전체 기능의 런타임 PASS 또는 완료된 실제 승리 연동을 주장하지 않는다.
- 남은 실전 연동: 스테이지 적 `enemy_set` 인스턴스 생성/증거 태그, 적·아군 전멸 판정, 실제 `BattleReport` 생성 및 신뢰 호출, 단계별 실배치/초기 진형 관측, Godot 파서·테스트·PC/Web 사용자 검증. 18초 데모 결과에는 정사 승리·단서·엔딩을 연결하지 않는다.
