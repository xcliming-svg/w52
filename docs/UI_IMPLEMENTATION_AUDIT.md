## 5. 2026-11-02 후속 UI 수정 — 드래그 경계·클리핑·배치 버튼 정렬

- **발견된 오류 1:** 기존 트리 연결선이 게임 루트 `Control`에서 직접 그려져 우측 전장 영역으로 시각적으로 넘어갈 수 있었다. 고정 패널 덮어그림만으로는 보장할 수 없어 `TreeClip`(좌측 1376×892, y=84, clip_contents=true) 안의 실제 자식 `TreeArt`에서 노드·선·라벨을 렌더링하도록 이동했다. 노드 정보와 스토리 대화는 클리핑 위의 별도 오버레이 `NodeInfoLayer`, `DialogueLayer`.
- **오류 2:** 정보창 배경 `_draw_popup()`과 배치 버튼 `_update_popup()`의 대화 중 상한 좌표가 달라 버튼이 카드 밖으로 보일 수 있었다. 하나의 `_popup_rect()` 계산으로 통합.
- **오류 3 (CI에서 실측):** UI 공통 버튼의 기본 최소 크기 500×74px가 실제 배치 버튼에도 남아 있었다. 대화 단계 실측 패널 `(788,418,390,274)`, 버튼 위치 `(993,612)`, 버튼 크기 `(500,74)`. `UI.make_button(text, minimum_size)`를 추가해 배치 160×62, 도움말 72×64, 배속 103×52, 전투 버튼 505×74를 생성 시점에 바로 적용. 이는 위치값만 손대지 않고 근본 원인을 수정한 것임.
- **추가 요구:** 마우스 왼쪽 드래그로 노드·연결선 전체를 이동. 8 논리 픽셀 이동 임계값으로 노드 클릭과 드래그를 분리하고, 기존 포커스 트윈 취소 후 현재 위치를 기준으로 이동. 전체 노드 경계에 대한 중앙 포커스와 64px 이동 한계 패딩을 동시에 보장하며, 대화/정보 패널·전장/도움말에는 드래그를 시작하지 않는다.
- **자동 회귀 테스트:** `tests/w52_ui_smoke.gd`에서 트리 클리핑 컨테이너·자식·오버레이 구조, 드래그 양방향 경계, 8px 임계값, 노드 클릭/드래그 구분, 정확한 노드 중앙 포커스, 대화 전후 정보창 안의 버튼 위치, 버튼 실제 크기, 기존 52주 흐름을 검증.
- **수정→실행 재검사:** 초기 CI `41361400641`에서 정보창/버튼 불일치로 실패 → 계측 CI `41361543911`에서 버튼 500×74px 원인 확인 → 수정 CI `41361760152`에서 Godot SceneTree 테스트, Import, Stable/Devel Web Export **성공**.
- **한계:** 헤드리스 테스트는 컨트롤 경계/동작을 확인하는 것으로, 실제 브라우저에서 렌더링된 픽셀 캡처·드래그 체감·클라이언트 육안 QA는 아직 미실시. 실제 게임 밸런스는 이번 수정과 무관함.

## 6. 2026-11-02 드래그 경계 재정의 — 사용자 수정 요구

- **이전 구현 해석 폐기**: "스킬트리 극단 노드의 중앙 위치에서 추가 ±64px 이동 허용"은 요청한 패딩 정의가 아니었다. 이전 5절의 "중앙 포커스와 64px 이동 한계 패딩 동시 보장"은 이 절의 새 규칙으로 대체한다.
- **새 불변 조건**: 트리 로컬 창 크기 1376×892px의 **안쪽 64px 안전영역 (64,64)~(1312,828)**을 넘어 트리의 어떤 노드, 확대된 노드, 연결선, 노드 라벨도 배치하지 않는다. 이는 창 가장자리를 기준으로 하는 여백이다.
- **계산 근거**: scripts/game.gd의 `_tree_content_bounds()`는 노드 중심만이 아니라 최대 확대 반경(38×1.12), 라벨의 실제 측정 폭, 라벨 하단까지 포함한다. `_pan_limits()`는 최소 이동 `64 - content.position`, 최대 이동 `TREE_RECT.size - 64 - content.end`로 클램프한다.
- **선택 포커스와 충돌 처리**: 가장자리 노드를 정확히 중앙으로 이동시키면 반대쪽 트리 일부가 화면 밖으로 나가므로, **내용 전체가 안쪽 64px에 들어오는 조건을 우선**한다. 중앙 포커스는 그 조건 내에서 가장 가까운 위치로 이동한다. 정확한 중앙 위치 보장 요구는 해당 조건과 양립하지 않는 경우에 한해 완화한다.
- **검증**: tests/w52_ui_smoke.gd는 초기/드래그 중/양축 최대·최소/선택 포커스 직후에 전체 경계 `_tree_content_bounds()`가 안전영역에 들어가는지 직접 검사하도록 변경. 초과하면 오류로 처리한다. 기존 버튼 크기·대화·클리핑·52주 진행 검증은 유지.
- **향후 레이아웃 규모**: 현재 노드 데이터는 64px 영역에 모두 들어온다. 장래에 트리 콘텐츠 크기가 1376−128 또는 892−128을 초과하면 모든 콘텐츠 표시가 물리적으로 불가능하므로, 기존 노드 크기를 조용히 바꾸지 말고 기획상 확대·축소나 분기 정렬을 별도 결정해야 한다.

## 7. 2026-11-02 패딩 최종 재정의 — 트리 극단 이동 제한

- **사용자 확인에 따른 수정**: 6절의 "전체 트리를 항상 안쪽 64px 안전영역에 유지"는 잘못 해석한 요구이며 **이 절로 대체**한다. 64px은 화면에서 항상 노출되는 여백이 아니다.
- **최종 요구**: 좌측 스킬트리 창 안의 나무를 자유롭게 드래그한다. 왼쪽 끝까지 끌면 **트리의 오른쪽 최외곽 콘텐츠가 창 왼쪽 경계에서 64px 안쪽**에 남는다. 오른쪽 끝까지 끌면 **트리의 왼쪽 최외곽 콘텐츠가 창 오른쪽 경계에서 64px 안쪽**에 남는다. 위아래도 동일하다. 그 밖의 가지는 창 바깥으로 나가며 TreeClip이 잘라내야 한다.
- **새 수식**: `low = Vector2(64,64) - content.end`; `high = tree_rect.size - Vector2(64,64) - content.position`. 노드 확대/라벨까지 포함한 기존 `_tree_content_bounds()` 재사용. 다른 정렬·선·대화창 기능은 변경하지 않는다.
- **거대한 트리 가운데 노드**: 현재 배율을 유지하면서 선택한 노드를 좌측 트리 중앙으로 가져온다. 그때 트리 양쪽 끝이 창 밖이어도 정상이며 64px 여백이 화면에 항상 보일 필요는 없다. 정확한 중앙 포커스와 극단 드래그 경계는 양립한다. 트리 전체를 동시에 보이게 하려면 별도의 확대·축소 기능이 필요하나 이 요구 범위는 아니다.
- **자동 검사 변경**: 전체 노드가 언제나 안전영역 안에 있는지를 검사하던 코드를 제거하고, **극단 드래그에서 반대편 최외곽 콘텐츠가 정확히 64px 남는지** 및 중간 포커스 상태가 허용되는지 확인한다. 기존 52주 진행·정보창 버튼·트리 클리핑 검사는 유지.
- **브랜치 운용**: 이번 후속 수정은 기존 기능 브랜치 `feature/w52-build-first-ui`를 계속 사용하며, 검증된 변경만 `devel`에 반영한다. `main`은 변경하지 않는다.
