# W52 UI 최종 구현·설계 교차검증 기록 — 2026-11-02

기준 설계: [UI_LAYOUT_DESIGN.md](UI_LAYOUT_DESIGN.md) (최종 단일 규격). 개발 범위는 Godot 4.7.2의 PC·Web 공용 W52 전략 UI, 52주 시연 흐름, 메뉴·저장 연결이다. 정식 전투·밸런스·고유 서사는 범위 밖이다.

## 1. 레거시 제거 범위

| 대상 | 최종 처리 | 기능 영향 |
|---|---|---|
| 스킬트리 과거 수치 패딩·전체 트리 경계 제한 | 상수·경계 함수·폐기 테스트 및 이전 설계 서술 제거. 노드 단위 완전 가시성 판정으로 통일 | 드래그·포커스 모두 노드 아이콘+이름 라벨 최소 1개 유지 |
| 예전 이동 데모의 플레이어 위치/이동 코드 | W52 `Control` 기반 게임 씬으로 교체된 상태를 유지하고 이전 게임 스크립트를 병용하지 않음 | 주차·전투 UI 단일 진입점 |
| 구 데모 색상 상수·사용되지 않는 글꼴 속성 | `scripts/ui_style.gd`의 사용되지 않는 `PLAYER_FILL`, `PLAYER_OUTLINE`, `custom_font` 및 관련 분기 제거 | 기본 상위 `Theme` 폰트/폰트 fallback을 계속 사용 |
| 구 이동 데모 저장 변환 | `scripts/save_manager.gd`의 저장 버전 1 변환 분기 제거. 저장/복구는 버전 2만 지원 | 이전 이동 데모 저장은 이어하기 불가. 현재 W52 버전 2 저장은 보존·복구 |
| 과거 구현 실패 내역·폐기 스펙 | 문서의 중복·상충 규칙 제거. 자세한 히스토리는 Git 이력과 Actions 기록에서 조회 | 설계서에는 현재 유효한 요구만 기재 |
| 실제 UI에 필요한 기존 기능 | `TreeClip`, 노드 정보창, 대화/메뉴/전투, Nanum 글꼴, 52주 테스트는 유지 | 사용 중인 기능을 레거시로 오인해 삭제하지 않음 |

## 2. 최종 설계 대 구현 교차검증

| 계약 | 관련 구현 | 자동검증·대조 기준 |
|---|---|---|
| FHD 16:9 및 고정 영역(왼쪽 트리/오른쪽 전장·로그) | `project.godot`, `game.gd`, `ui_style.gd` | 뷰포트 1920×1080 및 TreeClip (0,84,1376,892), 자식 TreeArt 검증 |
| 노드 최소 1개 완전 식별 | `_node_visual_rect()`, `_readable_tree_area()`, `_clamp_pan()` | 네 대각 극단값, 49개 임의 카메라 위치, 재투영 멱등성, 8개 노드 포커스 |
| 드래그·포커스 도중 트리 소실 방지 | `_update_pan()`, `_process()`의 카메라 보정 | 포커스 보간 12개 중간 프레임 및 대화창 위쪽 가시영역 |
| 노드/배경 드래그, 클릭·드래그 분리 | `_gui_input()`, `_input()`, `DRAG_THRESHOLD=8` | 8px 미만 클릭, 배경 이동, 노드 드래그 후 선택 불변 |
| 트리의 우측 전장 영역 침범 금지 | `TreeClip.clip_contents`와 그 자식 `TreeArt` | 클리핑 부모/자식·오버레이 속성 검증 |
| 정보창·배치 버튼 좌표와 크기 일치 | `_popup_rect()`, `UI.make_button(size)` | 대화 전/후 390×274 패널 안 160×62 버튼 포함 여부 |
| 대화 5개·도움말 제한·전장 배치·전투 흐름 | `scripts/game.gd` | 52주 전이, G·배치·도움말 미래 제한·중복 전투 시작 방지 |
| 저장 버전2 및 이전 버전 차단 | `main.gd`, `save_manager.gd` | 구 버전1 저장 거부, 버전2 저장·복원 |
| PC/Web 메뉴·폰트 공용 | `main.gd`, `ui_style.gd`, Nanum OFL subset, 모든 씬 | 소스 정적 대조, Godot 임포트, 안정/개발 Web Export |

## 3. 교차검증·수정 루프 종료 조건

1. 설계 단일 계약 → 실제 소스 상수·함수·좌표·상태 전이·표시 문자열과 항목별 대조한다.
2. 불일치 또는 정적/CI 실패 발생 시 해당 범위의 코드나 잘못된 설계 서술을 최소 수정하고 다시 대조한다.
3. 두 빌드의 Godot 임포트, 헤드리스 씬 및 52주 시나리오 테스트, 안정/개발 Web Export가 모두 통과해야 한다.
4. 이전 기능이 잘못 들어간 `devel` 전체 병합 없이 검증된 작업 브랜치만 `main`에 승격한다.
5. `main` 트리의 실제 안정판 빌드와 Pages 게시 성공을 별도 확인한다.

## 4. 검증 상태와 한계

- **소스 설계 대조**: 현재 설계 규격 기준으로 완료 처리할 항목을 위 행렬에 한정한다. 저장·폰트·클리핑의 호출 연결과 옛 함수 사용처를 확인한다.
- **자동 테스트**: `tests/w52_ui_smoke.gd` 및 `.github/workflows/deploy.yml`에서 안정판·개발판을 **각각** 테스트하고 Web Export 후 결과 파일을 검사한다.
- **릴리스 검증**: CI 실행 ID/상태와 `main` 최종 커밋은 빌드 및 게시 완료 후 이 절에 기록한다.
- **자동검증 외의 항목**: 실제 PC 조작, 모바일·웹 브라우저의 픽셀 단위 시각/포인터 이벤트 체감, 전투 AI·경제 밸런스·52주 고유 콘텐츠는 검증하지 않았다. 자동 테스트 통과만으로 실제 플레이 QA를 완료했다고 주장하지 않는다.
