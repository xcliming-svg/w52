## 3. 아직 검증하지 않았거나 기획 결정이 필요한 부분

- 실제 전투 AI·피해·승패 판정·유닛별 코스트는 미구현. 현재는 전투 관전 시간과 정해진 결과만 보여주는 동작 검증용 시연.
- 52주 고유 스토리/도움말 원고와 정확한 노드 해금 주차·경제값은 미확정. 반복 문구/임시 40G·70G·18초를 쓰므로 밸런스 검증 대상이 아님.
- 애니메이션의 실제 재생 품질, 1280×720에서의 읽기 편의, 팝업 충돌 및 클라이언트 웹폰트 렌더링은 직접 플레이 검수 필요.
- PC/Web 메뉴 조작, 저장소 지속성, 브라우저의 전체화면 권한, 52주 전체 사용감은 아직 실제 사용자 테스트 미실시.
- 로컬 C:\GPT-Workspace\w52의 Git 작업 상태 확인은 도구 제약으로 불가. 위 검증은 원격 feature/devel Git 트리 기준이며 로컬 작업트리를 동기화했다고 주장하지 않음.

## 4. 재대조 결론

- 요구된 화면 영역·폰트·노드/대화/전장 연동은 **코드 기준 정적 일치**.
- 기본 프로젝트 임포트, Godot SceneTree 52주 상태 스모크, Web Export는 **CI PASS**.
- 시각적 완성도와 정식 전투/스토리 콘텐츠는 **미검증·별도 후속 개발 범위**.
- main은 수정하거나 devel 전체를 병합하지 않음.

## 5. 2026-11-02 후속 UI 수정 — 드래그 경계·클리핑·배치 버튼 정렬

- **발견된 오류 1:** 기존 트리 연결선이 게임 루트 `Control`에서 직접 그려져 우측 전장 영역으로 시각적으로 넘어갈 수 있었다. 고정 패널 덮어그림만으로는 보장할 수 없어 `TreeClip`(좌측 1376×892, y=84, clip_contents=true) 안의 실제 자식 `TreeArt`에서 노드·선·라벨을 렌더링하도록 이동했다. 노드 정보와 스토리 대화는 클리핑 위의 별도 오버레이 `NodeInfoLayer`, `DialogueLayer`.
- **오류 2:** 정보창 배경 `_draw_popup()`과 배치 버튼 `_update_popup()`의 대화 중 상한 좌표가 달라 버튼이 카드 밖으로 보일 수 있었다. 하나의 `_popup_rect()` 계산으로 통합.
- **오류 3 (CI에서 실측):** UI 공통 버튼의 기본 최소 크기 500×74px가 실제 배치 버튼에도 남아 있었다. 대화 단계 실측 패널 `(788,418,390,274)`, 버튼 위치 `(993,612)`, 버튼 크기 `(500,74)`. `UI.make_button(text, minimum_size)`를 추가해 배치 160×62, 도움말 72×64, 배속 103×52, 전투 버튼 505×74를 생성 시점에 바로 적용. 이는 위치값만 손대지 않고 근본 원인을 수정한 것임.
- **추가 요구:** 마우스 왼쪽 드래그로 노드·연결선 전체를 이동. 8 논리 픽셀 이동 임계값으로 노드 클릭과 드래그를 분리하고, 기존 포커스 트윈 취소 후 현재 위치를 기준으로 이동. 최종 이동 한계는 아래 6절의 **최소 1개 노드와 라벨 완전 가시성** 조건을 적용한다.
- **자동 회귀 테스트:** `tests/w52_ui_smoke.gd`에서 트리 클리핑 컨테이너·자식·오버레이 구조, 드래그 양방향 경계, 8px 임계값, 노드 클릭/드래그 구분, 정확한 노드 중앙 포커스, 대화 전후 정보창 안의 버튼 위치, 버튼 실제 크기, 기존 52주 흐름을 검증.
- **수정→실행 재검사:** 초기 CI `41361400641`에서 정보창/버튼 불일치로 실패 → 계측 CI `41361543911`에서 버튼 500×74px 원인 확인 → 수정 CI `41361760152`에서 Godot SceneTree 테스트, Import, Stable/Devel Web Export **성공**.
- **한계:** 헤드리스 테스트는 컨트롤 경계/동작을 확인하는 것으로, 실제 브라우저에서 렌더링된 픽셀 캡처·드래그 체감·클라이언트 육안 QA는 아직 미실시. 실제 게임 밸런스는 이번 수정과 무관함.

## 6. 2026-11-02 최종 이동 한계 — 패딩 규칙 전면 제거

- **변경 배경:** 과거의 수치 기반 64px 이동 경계는 트리의 테두리 일부만 남기거나, 반대로 트리 전체를 화면 안에 가두는 동작을 초래했다. 사용자 요구는 **카메라를 어디로 움직여도 화면에서 어느 부분인지 식별할 만큼 트리의 일부가 계속 보여야 한다**는 것이다. 기존 `TREE_PAN_PADDING`, `_pan_limits()`, `_tree_content_bounds()` 및 이에 연관된 테스트/설계 규칙은 전부 제거한다.
- **명확한 완료 기준:** 카메라 드래그, 양쪽 대각 끝단, 노드 선택에 의한 자동 카메라 이동 모두에서 **적어도 1개 노드의 아이콘 전체와 이름 라벨 전체가 스킬트리 화면 안에 표시**된다. 라인 조각, 가장자리의 아주 작은 부분 등은 식별 가능한 콘텐츠로 인정하지 않는다.
- **실제 구현:** `game.gd::_node_visual_rect()`가 최대 확대 노드 반경 38×1.12 및 실제 폰트로 측정한 노드명 영역을 포함한 사각형을 생성한다. `_clamp_pan()`는 각 개별 노드가 전체 노드+라벨 상태로 보이는 카메라 영역의 합집합에 현재 카메라 요청 좌표를 투영하여 가장 가까운 유효 위치를 선택한다. **트리 전체를 둘러싼 사각형이나 고정 픽셀 패딩은 사용하지 않는다.**
- **오버레이 배제:** 대화창 표시 시 대화창으로 덮이는 아래쪽을 가시성 영역에서 제외하여 완전한 노드가 대화에 가려져 식별되지 않는 상황을 막는다. 기존 `TreeClip`은 연결선·노드가 오른쪽 전장에 그려지지 않게 계속 유지한다.
- **포커스 동작:** 중앙 노드를 선택하면 해당 노드를 화면 중심 (688,530)에 놓는다. 나머지 가지가 화면 밖으로 잘리는 것은 허용되며, 화면 크기에 관계없이 자동 축소하거나 항상 일정 여백을 강제하지 않는다.
- **검증:** `tests/w52_ui_smoke.gd`가 가시영역과 별도의 실제 노드명 사각형 목록을 대조하여 일관되게 완전히 표시되는 노드가 하나 이상 존재하는지 확인한다. 대각선 4방향 극단 드래그 및 선택 포커스, 대화 오버레이, 클릭과 드래그 구분, 기존 버튼 정렬과 52주 흐름 회귀검사를 유지한다.
- **검증 범위의 한계:** 픽셀 캡처 기반 브라우저 육안 검수와 장래의 수백 개 노드·불규칙 노드배치에서의 체감 연속성은 자동 테스트에 포함되지 않는다.
