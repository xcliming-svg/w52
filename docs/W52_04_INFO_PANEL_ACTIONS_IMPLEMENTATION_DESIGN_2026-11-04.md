# W52 구현설계 04 — 정보창 버튼·액션 연결·유보 함수 (2026-11-04)

- 상태: **구현 지시용 상세 설계**. 코드 미구현.
- 기준: `AGENTS.md`, `main` 3a85347295377557a7b2c57d539206c4f1d01518, 01~03·05 문서.
- 원칙: **버튼 1회 입력은 의미 있는 결과 또는 명시적 거부 사유를 가진다.** 구현할 수 없는 게임 규칙은 임의 구현하지 않고 함수 계약만 두며, 해당 버튼은 비활성/미노출 처리한다.
- 기능 범위: 하나의 고정 정보창의 하단 **주 행동 최대 1개, 문맥 보조 동작 0~1개**를 기본으로 하되 상세의 관련 유닛 링크/선행 시설 링크는 콘텐츠 영역에서 선택 가능. 불필요한 다중 버튼 UI를 만들지 않는다.

## 1. 기존 구현과 연결
- 현재 `scripts/game.gd`: `deploy_button.pressed → _action_selected()` → 종류에 따라 `_build_selected()` 또는 `_deploy_selected()`. `_update_popup()`가 버튼 표시/활성을 결정.
- 건설은 `phase in ["dialogue","prepare"]`, 부모 보유·최소 주차를 만족할 때만 즉시 소유 배열에 추가한다. 비용은 미확정이므로 G 차감 없음.
- 배치는 `phase in ["dialogue","prepare"]`·필수 시설/최소 주차·12개 슬롯을 검사한 뒤 배치 종류 ID를 추가한다. 현행은 위치 자동 결정이며 05에서 **빈 아군 칸 지정 후 확정**으로 바꾼다.
- `_action_selected()`와 단일 `deploy_button`의 책임을 '행동 정책 평가 → 안전한 수행'으로 명확히 재구성한다. 기존 `_build_selected()`, `_is_node_unlocked()`, `_find_node()`, `_has_building()`을 우선 재사용.

## 3. 가드/재진입/결과 처리
- 활성 조건은 버튼 렌더뿐 아니라 실제 핸들러에서도 **재검사**(노드·개체 존재, 주차, 단계, 부모·추가 시설, 보유, 슬롯, 셀 점유, 대상 유효성).
- 동일 버튼 중복 클릭: 이미 보유 건물 재구매 없음, 12칸 초과 없음, 배치 대기 중 `배치` 재누름으로 중복 유닛 생성 없음.
- 클릭 직후 동기적으로 모델 갱신 → 노드/경로, 해당 정보창, 배치 상태, 로그 순으로 refresh. 스크롤 및 선택 전환은 사용자가 명시한 경우에만 이동한다.
- 실패 시 원인을 정보창 또는 기존 로그에 짧게 제공하되 상태는 그대로 유지. 정책 미정인 행동은 사용 가능한 버튼으로 보이지 않게 한다.
- `시연 건설`은 비용 확정이 아니며 현행 무료 즉시 처리 유지, 건설 환불은 불가.
- 실제 배치 제거는 준비 단계에서만. 이번 시연은 무료 배치이므로 금전 환급 또는 보유권 취소를 처리하지 않는다.

## 4. 함수 책임 및 호출 계약(권장 명세)
**실행 기능(기존 함수를 재사용하고 필요한 연결만 구현):**
- `_resolve_info_context()` → `TREE_BUILDING | TREE_UNIT | FIELD_INSTANCE`와 유효 ID 반환.
- `_get_info_actions(context)` → 노출/활성/비활성 이유 결정 (뷰와 실제 상태 판정은 중복하지 않음).
- `_on_info_primary_action()` → 현재 컨텍스트 검사 후 건설·배치 대기·개체 제거 중 하나로 분배.
- `_build_selected()` → 기존 즉시 건설 가드/소유 갱신 유지.
- `_begin_new_unit_placement(unit_type_id)` → 05의 `PLACE_NEW` 진입, **아직 개체를 생성하지 않음**.
- `_cancel_pending_placement()` → 신규 위치 지정 대기만 종료.
- `_remove_placed_instance(instance_id)` → 준비 단계·개체 존재 검사 후 개별 개체 제거(05의 모델).
- `_focus_requirement(building_id)` → 필수 건물을 찾아 현재 트리에서 숨겨져 있으면 `full_tree_view`로 전환하고 해당 노드를 선택·포커스.
- `_show_related_units(building_id)` → NODES의 `requires`/부모 체인으로 관련 병종을 산출하고 동일 정보창 내 선택 링크 제공. 선택한 병종은 `_select_node()`로 포커스.
- `_return_to_tree_context()` → 전장 개체 선택만 해제하고 마지막 트리 노드(HQ 폴백) 정보로 복귀.
- `_refresh_info_panel()` → 현재 UI 및 버튼 상태를 단일 경로로 갱신.

**미결정 정책: 선언만 두고 실행 기능은 만들지 않는 경계:**
| 함수 자리(예시 이름; 새 세션에서 실제 참조에 맞춰 최소 구성) | 미결정 근거 | 현재 UI |
|---|---|---|
| `_request_upgrade_purchase(unit_id, upgrade_key)` | A/B 가격, 영구 소유, 추가 해금 조건, 실제 효과 미승인 | 구매 버튼 없음; A/B 조회만 |
| `_request_building_refund(building_id)` | 교차 선행 시설 환불과 저장 처리 미결정 | 환불 버튼 없음 |
| `_request_paid_unit_production(unit_id)` | 정식 생산 비용/물자 규칙 미승인 | 현재 무료 시연 배치만 |
| `_request_range_overlay(instance_id)` | HP/사거리 숫자·격자 거리 판정/사선 등 미정 | 사거리 표시 기능 없음, 값은 '미정' |
| `_request_combat_reposition(instance_id, cell)` | 전투 도중 유닛 이동 정책 미확정 | 전투 중 이동 불가 |

- 위 함수는 **입력·결과·검증 경계를 나타내는 미사용 비실행 스텁**만 허용한다. 내부에서 임의 자원을 차감하거나, 배열을 수정하거나, `pass` 후 성공을 반환하면 안 된다.
- 권장 스텁 구현은 `false`/실패 결과와 사유(`정책 미정`)를 반환하도록 하고 UI에서 호출하지 않는다. 필요한 최소 함수만 만들고 임의의 범용 이벤트 시스템을 구축하지 않는다.
- 정책 승인 전 스텁을 테스트로 성공 처리하지 않는다. '추후 연결'이라는 문구만 내고 실동작하는 버튼도 만들지 않는다.
