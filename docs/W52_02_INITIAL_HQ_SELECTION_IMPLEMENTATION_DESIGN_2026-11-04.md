# W52 구현설계 02 — 시작 시 HQ 선택 (2026-11-04)

- 문서 상태: **구현 지시용 상세 설계**, 코드 미구현.
- 기준: `AGENTS.md` 및 01 고정 정보창, 03 정보 요소, 05 전장 선택. `main` 3a85347295377557a7b2c57d539206c4f1d01518.
- 변경 대상: `scripts/game.gd`, `tests/w52_ui_smoke.gd`. 저장 스키마 확장은 이 기능만으로 요구하지 않는다.

## 1. 목표와 완료 조건
1. 새 게임으로 게임 씬에 처음 진입하면 **HQ 노드가 이미 선택**된 상태이고 고정 정보창에 HQ 설명이 나온다. 플레이어의 첫 클릭이 필요하지 않다.
2. 선택 상태·카메라·정보창이 동기화되어 HQ가 대화 레이어에 가려지지 않는다.
3. 복구된 게임도 저장 당시의 '선택 개체'가 기록되지 않은 현재 데이터 계약에서는 **HQ를 안전한 기본 선택**으로 사용한다.
4. 트리·우측 전장 선택을 시작하면 HQ 선택에서 자연스럽게 전환하고, 다른 사용자 선택을 매 프레임 강제로 HQ로 되돌리지 않는다.

## 2. 현행 경로와 수정
- 현재 `_ready() → _set_week_intro()`는 `selected_id=""`; `restore_state()`도 `selected_id=""`; 이 때문에 처음 정보창이 비어 있다.
- `_set_week_intro()`, `restore_state()`에서 데이터/주차와 보유 시설을 완성한 뒤 `selected_id="hq"` 또는 공통 `_select_initial_hq()`를 호출한다. 선택 초기화가 전장 개별 유닛 선택보다 앞서거나 나중에 잘못 덮어쓰지 않도록 공통 선택 컨트롤러(05)에 위임한다.
- 이미 코드에 있는 `camera_offset = _clamp_pan(TREE_CENTER_LOCAL - hq.p)`는 유지한다. 새 패널의 고정 위치는 선택 위치에 영향을 주지 않는다.
- 렌더/버튼 반영 시 `_refresh_all()` 및 고정 정보창 갱신이 빠지지 않게 한다.
- HQ는 기본 소유(`owned_buildings`에 반드시 포함). HQ에는 건설/배치 버튼을 표시하지 않는다.

## 3. 발생 시점별 규칙
| 발생 | 선택 규칙 | 정보창 | 카메라 |
|---|---|---|---|
| 새 게임 진입 / W01 첫 프레임 | HQ 선택 | HQ 보유/시작 경로 | HQ를 읽을 수 있게 중앙 포커스 |
| v2/v3 세이브 이어하기 | 선택 ID 미저장이므로 HQ 선택 | 현재 주차 기준 HQ 정보 | HQ 포커스 |
| 다음 주 진입 | 이전 주 배치 제거 후 HQ로 복귀(현행 선택 초기화의 빈값 대체) | HQ 정보 | HQ 포커스 |
| 기술트리의 다른 노드 클릭 | 해당 노드 우선 | 해당 노드 정보 | 선택 노드 포커스 |
| 전장의 기존 유닛 클릭 | 해당 개별 유닛 우선 | 개체 정보, 연결 병종 | 필요 시 해당 병종 포커스 |
| 전장의 빈 칸 클릭 | 개별 유닛 선택 해제, 마지막 트리 선택(HQ 기본) 복귀 | 트리 선택 정보 | 임의로 HQ 강제 포커스하지 않음 |
| 선택 없이 시작할 수 있는 전투·결과 단계 | HQ 포함 마지막 트리 선택 유지 | 읽기 전용으로 갱신 | 카메라 강제 이동 없음 |

## 4. 대화 자동 선택 정책
- 현재 `_advance_dialogue()`는 W01 세 번째 진행에서 `_select_node("rifle")`을 실행한다. 이는 기초 유닛 배치 튜토리얼 동선이다.
- 시작 프레임 HQ 선택을 보장하면서 **사용자가 이미 다른 노드/개체를 직접 선택했다면 튜토리얼의 소총병 자동 선택이 덮어쓰지 않도록** 구분한다. 아무 사용자 입력 없이 HQ 기본 선택만 남아 있다면 기존 소총병 안내 포커스는 유지한다.
- 자동 선택은 **W01 튜토리얼로 한정**한다. 현재 코드가 다른 주에서도 수행할 수 있으므로 코드/대사 정합성 검사 후 수정한다.
- 명시되지 않은 추가 자동 선택, 구매, 배치를 만들지 않는다.

## 5. 상태 경계
- `selected_tree_node_id`는 건물/병종 ID, `selected_instance_id`는 전장 개체 ID(05), `selection_origin`은 `tree`/`battlefield` 등 판별 근거로 사용. HQ 선택은 트리 컨텍스트 초기화이며 개별 유닛을 생성하지 않는다.
- 고정 정보창이 '닫힌다'는 개념 대신 다른 노드/개체로 **내용이 교체**된다. 전장 선택 해제 시 마지막 트리 선택을 보여 준다. 선택 무효 데이터는 HQ로 폴백한다.
- 일시정지/메뉴에서는 현재 입력을 차단한다. 복귀 시 선택 상태가 유효하면 유지한다.

## 6. 수용 검사 및 영향
- 메인 씬 실제 경로 `main.tscn → title → main menu → new game`에서 처음 게임 프레임의 HQ 선택·노드 강조·정보창 제목 확인.
- 모든 시작/복구/다음 주 경로에서 HQ 디폴트; 대화의 자동 소총병 선택이 **이미 한 사용자 선택을 덮어쓰지 않음**; W02 이상 불필요한 자동 소총병 선택 없음.
- HQ가 대화창 아래에 묻히지 않음. 선택 전환 후 정보창은 01의 고정 좌표 유지.
- v2/v3 저장 불러오기와 신규 저장 후 이어하기 회귀. 현재 버전에 선택 ID를 무리하게 추가하지 않음.
- 실제 브라우저 픽셀 QA는 별도. 구현 설계 대조 결과를 문서/감사 기록에 남긴다.

## 7. 다른 설계와의 연결
- 01의 고정 패널과 03의 HQ 콘텐츠 렌더가 먼저 또는 함께 구현되어야 첫 프레임의 정보창을 확인할 수 있다.
- 04의 버튼 상태 평가에서 `hq`는 '보유/조회' 전용이며, 05에서 전장 개체 선택과 HQ 기본 선택 간 전환을 정의한다.
