# W52 구현설계 05 — 우측 전장 배치·선택·이동·취소·트리 연동 (2026-11-04)

- 문서 상태: **구현 지시용 상세 설계**, 코드 미구현.
- 코드 기준: main 3a85347295377557a7b2c57d539206c4f1d01518 및 AGENTS.md; 01~04 정보창 설계와 연계.
- 핵심 조작: **우측 기존 유닛 클릭 = 개체 선택 + 배치 편집 가능한 상태**; **드래그 = 위치 이동**; **고정 정보창의 '배치 취소' = 해당 개체 1기 제거**. 별도의 '이동 버튼'이나 '편집 모드 전환 버튼'을 추가하지 않는다.
- PC/Web 공통 기능. 전투 중 이동·다중 선택·정식 능력치 수치 도입은 이번 범위가 아니다.

## 1. 현행 구현과 데이터 한계
- 현재 scripts/game.gd의 placements는 유닛 ID만 담는 Array[String]이며 개별 instance_id, 좌표, HP는 없다. _draw_field()는 배열 순서를 이용해 위치를 자동 계산한다. _deploy_selected()는 배치 버튼을 누르면 즉시 배열에 병종 ID를 추가한다.
- _click_ally()는 우측 전장 아군 유닛 클릭을 병종 노드 선택으로 연결하지만, 같은 병종 여러 기를 개별적으로 구분하지 못한다.
- 오른쪽 전장: Rect2(1376,84,544,652), 격자 한 칸 46×46 논리 px. 현재 _grid_size(): W01~13=6×6, W14~26=8×8, W27~39=10×8, W40~52=10×10. 상단 절반은 적군, 하단 절반은 아군, 전체 배치 한도 12기.
- 단계: dialogue, prepare, battle, result. 현재 건설/배치는 dialogue/prepare에만 허용되며, 주차 변경 시 배치 초기화·건물 보유 유지.

## 2. 조작 및 상태 전이
두 종류의 개념을 구분한다: '새 병종 배치 위치 지정'은 명시적 PLACE_NEW 상태가 필요하나, **기존 개체를 선택하면 즉시 편집 가능한 상태**이므로 별도 MOVE_MODE 버튼·상태는 필요하지 않다.

| 현재 상태 | 입력 | 필수 결과 |
|---|---|---|
| 트리 병종 선택·해금·12칸 미만 | 정보창 '배치' | PLACE_NEW 진입, 배치 가능한 아군 빈 칸 안내; **아직 개체 생성하지 않음** |
| PLACE_NEW | 빈 아군 칸 1회 클릭 | 새 instance_id를 가진 유닛 정확히 1기 생성, 그 개체 선택·정보창 표시, NORMAL 복귀 |
| PLACE_NEW | 점유 칸/적군/범위 밖 클릭 | 생성하지 않고 대기 유지, 불가 원인 안내 |
| PLACE_NEW | 정보창 '위치 지정 취소' | 대기만 종료, 트리 병종 정보로 복귀; 기존 개체 제거 없음 |
| NORMAL·기존 아군 유닛 | 8px 미만 움직임으로 클릭 | 개체 선택 테두리, HP/사거리 정보(실제 데이터만), 트리 병종 강조, 편집 가능 컨텍스트 |
| NORMAL·기존 아군 유닛 | 8px 이상 드래그하여 빈 아군 칸에 놓기 | instance_id 유지, grid_cell만 변경, 그 개체 선택 유지 |
| NORMAL·기존 아군 유닛 | 점유/적군/범위 밖에 놓기 | 원래 셀 유지, 개체 복제·소멸·교환 없음 |
| NORMAL·선택 개체 | 정보창 '배치 취소' | 선택한 개체 1기만 제거, 병종 해금·시설 보유·G 변경 없음 |
| NORMAL·빈 아군 칸 | 클릭 | 전장 개체 선택만 해제, 마지막 트리 노드(HQ 폴백) 정보로 복귀 |
| battle/result | 아군 개체 클릭 | 정보 및 트리 병종 강조만 허용 |
| battle/result | 배치·드래그·배치 취소 | 불가, 개체/위치 불변 |

- 단순 클릭은 이동이 아니다. 드래그를 시작해도 실제 모델의 위치 변경은 유효한 셀에서 포인터를 놓을 때 **한 번만** 일어난다.
- PLACE_NEW 중 기존 유닛 클릭은 다른 개체 선택이 아닌 점유 불가 안내. 취소 후 기존 개체 선택 가능. 배치 대기가 중복 시작되어 2기를 생성하지 않도록 한다.
- 한 기가 있는 셀로 이동하려고 놓으면 교환하지 않고 이동을 거부한다.
- 전투 준비 중에만 새 유닛 배치, 기존 유닛 드래그·제거 가능. dialogue 단계는 기존 코드가 허용하므로 유지(대화 레이어 클릭과 혼선 없이). 전투 중에는 개체를 선택해 정보만 볼 수 있다.
- ESC는 main.gd의 일시정지와 충돌하므로 **명시적 '위치 지정 취소' 버튼**을 필수로 제공한다. ESC를 별도 취소로 매핑하려면 이벤트 우선순위와 기존 ESC 동작 검증 후에만 적용한다.

## 3. 선택의 단일 소유권과 동기화
- 상태 필드 권장: placement_mode = NORMAL 또는 PLACE_NEW, selected_tree_node_id(기본 hq), selected_instance_id(없으면 빈 문자열), pending_unit_type_id(PLACE_NEW에서만 유효).
- 정보창의 활성 컨텍스트: 유효한 selected_instance_id가 있으면 전장 **개체** 정보, 없으면 selected_tree_node_id의 **종류/건물** 정보. 한 번에 두 개의 정보창을 띄우지 않는다.
- 트리 노드 직접 클릭 → 개체 선택 해제, 배치 대기는 취소, 해당 트리 정의 정보 표시. 전장 개체 클릭 → 같은 unit_id의 **트리 노드/부모 경로만 시각 강조**; 이 때문에 현재 정보창이 병종 기본값으로 바뀌면 안 된다.
- 전장 개체 클릭 시 병종 노드가 가시 영역 밖이라면 한 번만 부드럽게 포커스하고, 이미 화면에 읽을 수 있게 보이면 카메라를 옮기지 않는다. 개체를 드래그하는 동안 트리 카메라는 움직이지 않는다.
- 선택 이벤트의 상호 재발행(트리 선택 → 전장 선택 → 다시 트리 선택)으로 무한 루프가 생기지 않도록 한다.
- 전장 빈 칸 클릭은 개체 선택만 해제하고 마지막 트리 선택을 유지한다. HQ 기본/주차 시작은 02를 따른다.
- 정보창의 절대 좌표와 전장 크기는 선택/이동에 의해 바뀌지 않는다(01).

## 4. 개별 유닛 자료 모델
최소 실제 구현 자료는 다음과 같이 사용한다. 필드 이름은 기존 코드 충돌을 확인하여 정한다.

| 필드 | 형태 | 불변 조건 |
|---|---|---|
| instance_id | 고유 문자열 | 여러 소총병도 서로 다른 ID, 이동 후 동일, 저장·복구 후 유지 |
| unit_id | NODES에 존재하는 병종 ID | kind=unit이며 주차·필수 시설 조건을 만족 |
| grid_cell 또는 col,row | 격자 정수 좌표 | 아군 영역 안, 모든 개체 간 셀 중복 0 |
| hp_current | **미도입** | 전투 시스템 수치가 확정된 뒤에만 추가 |

- placements:Array[String]를 최소한 Array[Dictionary]의 {instance_id, unit_id, col, row}로 전환한다. 위치와 ID를 리스트 인덱스로 대체하지 않는다.
- HP/최대 HP/사거리/공격력 등은 정의된 실제 모델에서 읽는다. 현재 정식 수치가 없으므로 가짜 100HP, 3칸, 무작위 공격력을 넣지 않는다.
- 기존 배치 한도 12기를 유지한다. 배치/이동/취소는 건물 보유, 유닛 해금, G에 영향을 주지 않는다.

## 5. 격자/히트 테스트/드래그 계약
- _grid_size() 및 격자 원점/46px 간격은 **단일 계산 경로**로 사용하여 그리기·클릭·드래그 미리보기·저장 셀 변환이 어긋나지 않게 한다.
- 스크린 좌표 → 셀 좌표 변환 함수, 아군 유효 셀 함수, 해당 셀 점유 개체 조회 함수를 마련한다. 기존 _click_ally()의 배열 인덱스 기반 판정은 대체한다.
- 드래그 시작 시 선택 개체 ID/원래 셀/마우스 시작 위치 기록, 움직임 8px 미만은 클릭, 이상만 이동 후보 셀 프리뷰. 손을 놓으면 유효성 재검사 후 위치 1회 확정.
- 정보창의 버튼·스크롤은 전장 드래그/기술트리 드래그가 시작되지 않게 소비; 필드 입력이 TreeClip으로 전달되지 않음. 대화창과 우측 전장/좌측 기술트리 입력 충돌 방지.
- 적군 유닛을 선택/배치 변경하는 기능은 추가하지 않는다. 기존 타이머 시연 전투를 유지한다.

## 6. 저장 데이터 계약과 구버전 호환
- 위치 없는 기존 v3 placements를 사전 개체 포맷으로 조용히 재정의하지 않는다. **SAVE_VERSION=4 증가를 권장**한다.
- v4 기존 week,g,phase,dialogue,help,buildings 유지 + placements:Array[Dictionary] 요소 {instance_id:String, unit_id:String, col:int, row:int}. HP 미도입 시 HP 항목 저장하지 않음.
- v4 로드 검사: 필수 필드 자료형, 고유/비어 있지 않은 ID, 병종 유효성, 현재 주차·건물 조건, 12기 제한, 아군 영역, 격자 범위, 점유 중복 검사. 잘못된 저장은 정책에 따라 명확히 거부하고 부분 통과를 숨기지 않는다.
- v2/v3 읽기는 기존 문자열 배열 순서를 **해당 주차의 기존 자동 배치 좌표**로 전환; 유효하지 않은 구 시연 유닛 ID는 기존 원칙대로 제외. v1은 계속 거부.
- 새 게임은 개체 0기, 다음 주차 진입은 배치 초기화·건물 유지. 저장 → 이어하기에서 같은 주차 개체 ID와 위치가 재현되어야 한다. battle 저장 상태는 기존처럼 prepare로 복구한다.
- 현재 save_manager.gd v3의 _valid_buildings 건물 부모·주차 검증을 후퇴시키지 않는다.

## 7. 필수 테스트 케이스
1. 게임 진입 HQ 선택, 트리 소총병 선택 → '배치' 버튼만으로 0기 → 빈 아군 칸 클릭 후 1기 생성/정보창 개체 전환.
2. 같은 소총병 2기 다른 위치에 배치 → 각각 개별 클릭하면 서로 다른 instance_id/위치, 트리 노드는 소총병 하나만 강조.
3. 기존 소총병 A를 빈 칸 B로 드래그 → A 셀 비고 B에 같은 ID 1기만 존재; 동일 정보창 유지.
4. 점유 셀/적군/영역 밖 드롭은 원위치. 8px 이하 움직임은 단순 선택. 배치 도중 다른 곳을 눌러도 중복 생성 금지.
5. 정보창 '배치 취소' → 선택한 ID 1기만 제거; 다른 유닛·G·건물 상태 불변.
6. 12기 채우면 배치 비활성화, 제13기 차단. 전투/결과 중 선택은 가능하나 이동/취소/배치 차단.
7. 트리 선택 ↔ 전장 개체 선택 ↔ 빈 셀 클릭 전환에서 정보창/경로/카메라 동기화, 반복 선택 루프 및 드래그 중 카메라 이동 없음.
8. W13→14, W26→27, W39→40 격자 크기 경계에서 좌표 판정 검사. 배치 초기화와 52주 진행, 도움말/대화/ESC/전투 시연 회귀.
9. v2/v3 로드→v4 저장→재개, v4 ID/셀 중복·적군 셀·범위 밖·미존재 병종·주차 불만족 거부, v1 계속 거부.
10. 정보창과 전장의 포인터 입력 분리, TreeClip 20노드/19선, 포커스·패닝 49점 회귀, Godot 헤드리스 씬/웹 Export. 실제 브라우저 QA는 별도로 검증 표시.
