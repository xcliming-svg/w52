# w52 게임 실행 흐름 및 기본 UI 설계

- 문서 상태: 승인된 요청 반영 / 구현 기준
- 기준 엔진: Godot 4.7.2, GDScript, GL Compatibility, Web
- 작업 범위: 타이틀 → 메인 메뉴 → 게임 진입/재개 → 일시정지/설정 → 패배 → 재시작/메인 복귀
- 비범위: 전투, 유닛, 라운드, 승리/패배 판정, AI, 네트워크, Steam 연동, 정식 에셋

## 1. 기존 프로젝트 및 보존 사항
기존 `main.tscn`/`main.gd`에 원형 플레이어와 WASD/방향키 이동 데모가 있다. 이 이동/렌더링 코드는 `scenes/game.tscn` + `scripts/game.gd`로 옮겨 유지한다. 기존 웹 Compatibility 렌더링, 해상도, export/CI 워크플로 및 AGENTS.md 규칙을 유지한다.

## 2. 화면 전이
1. 실행 직후 타이틀 화면 표시. 추가 키 입력이나 클릭 요구 없이 **1.5초 후 메인 메뉴 자동 전환**. 추후 로고/인트로 에셋을 끼울 수 있다.
2. 메인 메뉴: **새 게임 / 이어하기 / 설정 / 게임 종료(PC에서만)**. 저장 없으면 이어하기 비활성화. 웹에서 게임 종료 항목 숨김.
3. 새 게임: 이전 세션을 초기화하고 게임 씬 생성. 현재 게임 씬은 이동 데모이며 전투 로직 없음.
4. 게임 중 ESC: 게임을 정지하고 일시정지 메뉴(계속하기 / 다시 시작 / 설정 / 메인 메뉴) 오버레이 표시. ESC 또는 계속하기로 해제.
5. 설정: 메인 메뉴와 일시정지에서 진입 가능. 뒤로 가기 및 ESC로 이전 화면 복귀. 일시정지에서 열었으면 게임은 계속 정지.
6. 메인 메뉴 복귀: 현재 게임 위치를 저장하고 게임 씬 정리. 이어하기는 이 저장 상태를 로드한다.
7. 패배: 게임 로직에서 `defeated` 신호를 전달한 경우만 패배 오버레이 표시. 진행 저장은 삭제하고 다시 시작 / 메인 메뉴 제공. **F9 등의 임시 패배 테스트 입력 없음.** 현재는 패배 판정 자체가 없으므로 게임플레이로부터 발생하지 않는다.
8. 다시 시작: 기존 게임 씬과 저장 상태를 버리고 초기 상태로 새 게임 생성.

## 3. 책임 및 데이터 소유
- `main.tscn`, `main.gd`: 단일 상위 화면 조정자; 게임 세션 생성/종료, 메뉴, 설정/오버레이와 상태 전이, 일시정지.
- `scenes/title.tscn`: 키 입력 없이 자동 전환되는 타이틀.
- `scenes/main_menu.tscn`: 메뉴 버튼 및 저장 유무에 따른 이어하기.
- `scenes/game.tscn`, `scripts/game.gd`: 게임 공간/현재 임시 WASD 이동 및 `defeated` 이벤트 계약.
- `scenes/pause_menu.tscn`, `scenes/defeat_screen.tscn`: 두 오버레이.
- `scenes/settings_menu.tscn`: 오디오/화면 설정 표시, 변경 및 복귀.
- `scripts/save_manager.gd`: `user://game_save.cfg`에 최소 진행 저장. 위치, 스키마 버전만 기록. 유효하지 않은 저장을 무시/비활성화하며 오류를 경고.
- `scripts/settings_manager.gd`: `user://settings.cfg`에 환경설정 저장. 마스터/음악/효과 음량과 전체화면 상태를 관리.
- `scripts/ui_style.gd`: 공통 배경/패널/버튼/색상/폰트 슬롯을 한 곳에서 지정. 실제 팔레트 확정 시 이곳을 교체.

## 4. 화면 상태와 입력
`TITLE, MAIN_MENU, PLAYING, PAUSED, DEFEAT`를 상위 조정자가 소유한다. 설정 메뉴는 화면 상태가 아니라 현재 메뉴 위에 놓이는 오버레이로 처리해 메인/일시정지 출발점을 보존한다. 게임플레이 입력은 PLAYING에서만 허용. 씬 트리 정지 시 게임 노드는 PAUSABLE, 상위 UI는 ALWAYS 모드. ESC는 게임에서 PAUSED, PAUSED에서 PLAYING, 설정에서는 이전 메뉴로만 복귀. 다중 클릭/중복 이벤트에서 잘못된 전이를 차단한다.

## 5. 실제 사용 가능한 설정
- 마스터·음악·효과 음량(0–100%, AudioServer 버스 Master/Music/SFX 사용). 아직 음악/효과 파일 및 플레이어 재생은 없음.
- 전체화면/창 모드 선택; 지원 플랫폼에서 DisplayServer API 사용.
- 변경 즉시 적용 및 `user://settings.cfg`에 저장.
- 미지원 입력장치/언어/그래픽 프리셋/해상도 목록은 이번에 추가하지 않는다.

## 6. 에셋 연결점(파일은 아직 추가하지 않음)
- 타이틀/메뉴의 비어 있는 TextureRect: 로고, 배경 삽입 위치.
- 게임 화면의 비어 있는 TextureRect: 향후 배경 아트 삽입 위치.
- 씬의 비어 있는 AudioStreamPlayer: 향후 BGM/효과음 연결 위치. 실제 사운드는 미등록.
- 테마에 선택적으로 연결할 사용자 Font 슬롯: 폰트 미등록 시 기본 폰트.
- 각 UI 컬러는 `ui_style.gd`를 통해 적용. 이후 팔레트 교체는 한 곳에서 수행.
에셋 경로가 없다고 해서 실패하도록 `preload()`하거나 가짜 파일/파이프라인을 만들지 않는다.

## 7. 최소 저장 계약
- 현재 오브젝트 좌표(Vector2) 및 버전(1)만 저장. 저장은 게임에서 메인 메뉴로 나갈 때 수행.
- 새 게임/재시작/패배: 기존 진행 저장 제거. 이어하기: 저장 유효성 확인 후 복구.
- 저장 파일 없음/데이터 손상/범위 초과 시 이어하기 비활성화. 저장 실패는 로그로 보고하고 게임 상태를 손상시키지 않는다.
- 현재는 체크포인트·라운드 저장이 없다. 실제 게임 규칙 추가 때 기존 스키마를 검토/버전업한다.

## 8. 구현 순서와 완료 기준
1. 최신 origin/main 기반 `feature/game-flow-ui` 작업 브랜치 준비.
2. 이 문서를 `docs/game-flow-design.md`로 먼저 저장.
3. 공통 UI 스타일, 설정/저장 코드, 씬 및 상태 조정자, 기존 이동 코드 이전.
4. 정적 참조·스크립트·설정 검사 후 수정 반복. 작업 브랜치 내 검증이 가능하면 수행.
5. 해당 기능 변경만 `devel`에 반영. GitHub Actions의 헤드리스 씬 검사/Web Export/Pages 게시 결과를 별도로 확인.
6. `main`에는 자동 반영하지 않음. 사용자 플레이 QA/성능 측정/실제 게임플레이 정상성은 이번 검증에서 제외.

## 9. 제외 및 후속 연결
패배 신호는 향후 게임 판정에서 연결할 실제 인터페이스만 제공한다. 승리 UI, 난이도, 전술 전투, 라운드, 상점, 인벤토리, 멀티플레이, 번역, 설정의 복잡한 프리셋, 로고/폰트/음악 파일 자체는 구현하지 않는다.
