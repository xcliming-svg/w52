# W52 구현설계 01 — 고정 노드 정보창 (2026-11-04)

- 문서 상태: **구현 지시용 상세 설계**, 코드 미구현. 좌표·레이아웃은 1920×1080 논리 해상도의 **제안 기본값**이며 시각 QA에서 조정 가능.
- 기준: `AGENTS.md`, `docs/UI_LAYOUT_DESIGN.md`, `docs/WW52_TECH_TREE_IMPLEMENTATION_DESIGN_2026-11-04.md`.
- 코드 기준: `main` 3a85347295377557a7b2c57d539206c4f1d01518 (`devel` 0e11827b72da6554fe6e62b3a762c890b713fdad와 같은 게임 트리). PC/Web 동일 씬.
- 연관 문서: 02 초기 HQ, 03 정보 요소, 04 버튼 액션, 05 전장 조작. 이 문서만으로 게임 룰·HP 수치를 만들지 않는다.

## 1. 목표와 완료 조건
1. 노드 클릭·전장 유닛 클릭·트리 드래그 시 정보창의 **위치와 크기는 변하지 않는다**. 기존 노드 추적 팝업을 고정 도킹 패널로 대체한다.
2. 기술트리(병종/건물 정의)와 우측 전장 개별 유닛이 **하나의 고정 정보창**을 공유한다. 누가 선택했는지만 콘텐츠가 바뀐다.
3. 정보창은 전장, 헤더, 전투 버튼, 도움말, 대화창과 겹치지 않으며 패널 내부 스크롤로 긴 정보를 처리한다.
4. 트리 20노드/19연결선, 선택 112%, 드래그 임계값 8px, 스킬트리 전체/기본 모드, PC/Web 공통 동작을 유지한다.

## 2. 현재 구현과 변경 범위
- 현재 `scripts/game.gd`: `POPUP_SIZE=(390,274)`, `_popup_rect()`가 노드 `_node_screen()` 위치를 따라 이동; 별도 `_upgrade_rect()=(420,256)`; `_update_popup()`가 `deploy_button`를 `_popup_rect()`에 맞춰 옮김.
- `TreeClip`은 `Rect2(0,84,1376,892)`, 전장은 `Rect2(1376,84,544,652)`, 대화창은 `Rect2(28,778,1320,171)`. 기존 정보창 위치를 사용하는 스모크 테스트는 변경되어야 한다.
- 변경 예상: `scripts/game.gd`의 정보창 레이어/Control 구성, 선택 처리·입력 판정·패닝 클램프, `tests/w52_ui_smoke.gd`의 정보창 및 포커스 계약. 기존 `UI.make_button` 재사용. 관련 없는 씬/메뉴는 변경하지 않는다.

## 3. 고정 좌표와 레이아웃 계약
| 항목 | 초기 구현 제안 | 계약 |
|---|---|---|
| 패널 외곽 | `Rect2(930,170,420,560)` | 좌측 트리 내부, 오른쪽 끝 26px 여백, 하단 730px |
| 상단 제목/상태 | 높이 약 80px | 스크롤해도 제목·상태 확인 가능 |
| 중간 내용 | 세로 스크롤 | 3개 선행 조건, A/B 강화 및 능력치까지 오버플로 허용 |
| 하단 액션 | 높이 약 66~80px | 스크롤과 독립 고정, 버튼은 04 문서의 상태 규칙 사용 |
| 전장 | x>=1376 | 패널이나 버튼이 침범하지 않음 |
| 대화 레이어 | y>=778 | 패널 하단 730px으로 독립 |
- 위 수치는 최종 미술 수치가 아니다. **고정 위치·비겹침·액션 가시성**이 불변 조건이며 구현 중 폰트/스크롤 실측으로 조정한다.
- 창의 닫기/비선택 처리는 02·04의 선택 복귀 규칙을 따른다. 기본은 패널을 항상 표시하며, 선택 컨텍스트가 없으면 HQ를 기본 컨텍스트로 사용한다.
- 24개 A/B 강화는 트리 아이콘/선으로 추가하지 않는다. 현재의 별도 떠다니는 강화 카드 대신 **고정 정보창의 유닛 상세 섹션**으로 통합한다(03에서 내용 정의).

## 4. 입력과 카메라 경계
- 정보창 전체는 클릭·휠·드래그 시작을 **트리 패닝보다 우선 소비**한다. 정보창 내부 스크롤을 트리 이동으로 오인하지 않는다. 버튼 입력은 해당 Button 신호로 처리한다.
- `_popup_rect()`의 노드 상대 위치 계산을 제거하고 `_info_panel_rect()` 같은 단일 고정 사각형을 도입한다. 실제 Control 위치/크기와 입력 판정은 그 하나의 값을 사용한다.
- 선택 노드 포커스의 기존 목표 화면 좌표 (688,530)는 유지한다. 패널이 항상 x930부터 시작하므로 중앙 포커스 시 선택 노드 아이콘과 라벨이 가려지지 않는지 검증한다.
- 기존 `_readable_tree_area()`/`_clamp_pan()`는 패널 아래 보이지 않는 노드만으로 '완전한 노드 하나 가시'를 충족했다고 오판할 수 있다. **패널을 제외한 읽을 수 있는 좌측 영역**(예: 트리 로컬 x=0..918)과 대화창 위 높이를 기준으로 완전한 아이콘+라벨 가시성을 검증하고, 포커스 중/드래그 중에도 유지한다. 필요하면 가시영역을 복수 사각형으로 표현하되 과도한 추상화는 피한다.
- 기본 트리/전체 기술도 전환과 전장 선택에 따른 노드 강조는 패널 좌표를 바꾸지 않는다.
- 화면 스트레치 및 1280×720 실제 창 크기에서 CanvasItem 논리 좌표와 입력 좌표계의 일치를 확인한다. PC/Web 분기 UI를 만들지 않는다.

## 5. 구현 순서와 관련 영향
1. `InfoPanel` 또는 기존 `NodeInfoLayer`를 고정 Control로 전환하고, 제목/스크롤/버튼 영역을 구조적으로 분리한다.
2. 기존 `_draw_popup`와 `_draw_upgrade_panel`의 역할을 03의 공통 렌더/갱신 구조로 옮긴다. 중복 패널이 남지 않게 한다.
3. 정보창 입력 차단과 TreeClip 패닝·선택 우선순위를 맞춘다.
4. 고정 정보창을 제외한 가시 노드 검사와 포커스 경계를 업데이트한다.
5. 02~05의 선택·데이터·버튼 연결을 동일 패널에 적용한다.

## 6. 검증 항목
- 처음 HQ 선택, 20개 각 노드 선택, 전장 개체 선택, 8px 클릭/드래그, 카메라 보간 12프레임, 49개 팬 지점에서도 정보창 좌표가 불변.
- 3개 선행 조건과 A/B 강화가 포함되어도 글자/버튼이 패널을 벗어나지 않음; 실제 폰트 측정.
- 전장·대화·헤더·도움말 비겹침; 클릭·스크롤·드래그 입력 분리; 패널 아래 노드를 '가시'로 오판하지 않음.
- 헤드리스 씬/저장 호환성/웹 Export는 기능 브랜치에서 검사하고, 실제 웹 픽셀·포인터 QA는 별도로 미검증 표시.
- 구형 정보창의 좌표 고정 테스트(`_popup_rect`, `_upgrade_rect`, `POPUP_BUTTON_OFFSET`)는 새 고정 패널 계약으로 대체한다.

## 7. 유보와 금지
- 정식 능력치, 가격·결제, 강화 구매, 전투 이동 정책은 본 문서에서 확정하지 않는다.
- 새 별도 상세 화면이나 독립된 웹 전용 패널을 추가하지 않는다.
- 기존 게임 노드/선/구매 규칙과 저장을 단순 레이아웃 수정만으로 변경하지 않는다.
