# w52 게임 화면 구성 — 구현설계 대조 및 수정 기록

- 감사 범위: `docs/game-flow-design.md`와 `feature/game-flow-ui`의 화면 구성 기능
- 점검 기준일: 2026-11-01
- 확인 방법: 실제 `.gd`, `.tscn`, `project.godot`, `AGENTS.md`, `README.md`의 정적 코드·참조 대조
- 실행 제한: 사용자 플레이 QA, 브라우저 UI 자동화, 게임 로직/밸런스 검증은 수행하지 않음
- 상태 표기: **정적 일치**는 코드·리소스·상태 전이 구조에 대한 확인이며 실제 사용 중 정상동작 보증이 아님

## 1. 설계 요구사항별 정적 대조

| 승인 구현 요구사항 | 구현 근거 | 대조 상태 |
|---|---|---|
| 타이틀 키 입력 없이 자동 이동 | `scripts/title.gd`의 1.5초 타이머 및 `main.gd`의 `finished` 연결 | 정적 일치 |
| 메인 메뉴 새 게임/이어하기/설정/종료 | `scripts/main_menu.gd`의 4개 버튼·신호 | 정적 일치 |
| 이어하기 표시 및 저장 없을 때 비활성 | `continue_button.disabled`, `main.gd`의 `save_store.has_save()` | 정적 일치 |
| 새 게임 시작은 이전 진행 초기화 | `main.gd`의 `_start_new_game` 및 `_start_game` | 정적 일치 |
| 현재 임시 오브젝트 이동 유지 | `scripts/game.gd`의 WASD/방향키 및 드로잉 | 정적 일치 |
| ESC 일시정지/계속/재시작/메인 | `main.gd`의 `_input`, `_pause_game`, `_resume_game` 및 `scripts/pause_menu.gd` | 정적 일치 |
| 일시정지에서 설정을 열어도 게임 정지 유지 | `get_tree().paused` 및 `Main`의 `PROCESS_MODE_ALWAYS` | 정적 일치 |
| 메인/일시정지 양쪽 설정 진입 | `main.gd`에서 같은 `_open_settings`에 신호 연결 | 정적 일치 |
| 음량 저장 및 버스 적용 | `scripts/settings_manager.gd`에서 `ConfigFile`, `AudioServer` 사용 | 정적 일치 |
| PC/Web 같은 전체화면 UI | `scripts/settings_menu.gd`에서 토글 공유 및 `settings_manager.gd`의 플랫폼별 시작 제약 처리 | 구조 일치, 실제 웹 입력 미검증 |
| 게임 메인 복귀 시 저장, 이어하기 복구 | `_leave_game_to_menu` → `save_game` 및 `_continue_game` → `load_game` | 정적 일치, 파일 지속성 미검증 |
| 패배 신호 → 패배 화면/재시작/메인 | `scripts/game.gd`의 `defeated` 신호, `main.gd`의 `_on_defeated` | 구조 일치, 패배 판정 미구현(예정) |
| F9 테스트 키 없음 | 입력 스크립트에 임시 F9 호출 없음 | 정적 일치 |
| PC/Web 같은 종료 버튼과 동작 | `scripts/main_menu.gd` 및 `main.gd`의 `get_tree().quit()` | 정적 일치, 실제 웹 종료 상태 미검증 |
| 추후 로고/배경 삽입 슬롯 | `scenes/title.tscn`의 `LogoArt`, 타이틀/메인 메뉴 `BackgroundArt`, 게임 `Sprite2D` | 정적 일치 |
| 추후 BGM·SFX 슬롯 | `main.tscn`의 `MenuMusic`, `GameMusic`, `UISound` | 정적 일치 |
| 한국어 글꼴 및 공통 팔레트 | `main.gd`의 UI 테마 폰트, `scripts/ui_style.gd`의 색상 | 정적 일치 |
| 별도 Web 버전 없음 | PC·웹 단일 씬 및 스크립트, Web export 프리셋만 별도 | 정적 일치 |

**이어하기 조건:** 메뉴에는 처음부터 버튼이 표시되지만 저장 파일이 없으면 비활성화된다. 단순 실행 또는 새 게임 시작만으로 활성화되지 않는다. 게임 중 **ESC → 일시정지 → 메인 메뉴**를 선택하면 임시 플레이어 위치를 저장한다. 유효한 저장이 생긴 다음에는 이어하기가 활성화된다. 새 게임/재시작/패배에서는 기존 저장이 제거된다. 웹 브라우저 저장소의 실제 유지 여부는 미검증이다.

## 2. 설계 대조 → 수정 → 재대조 루프 기록

### 1차 대조 — 불일치 발견 및 시정
1. 타이틀 로고 슬롯이 문서에 명시되어 있으나 씬에는 배경 슬롯만 있음 → `scenes/title.tscn`에 `LogoArt`를 마련하고 `scripts/title.gd`에서 레이아웃에 연결.
2. 설계 문서에 게임 배경을 `TextureRect`로 설명했지만 실제 게임은 `Node2D/Sprite2D` → 문서 설명을 현재 씬의 `Sprite2D`와 일치하도록 정정.
3. 향후 교체할 전체 팔레트가 UI에만 중앙 관리되고 기존 게임 드로잉의 색은 하드코딩 → `scripts/ui_style.gd`에 게임 색상 상수를 두고 `scripts/game.gd`에서 참조. 기존 표시 색상 자체는 유지.
4. 이어하기가 언제 활성화되는지 설계와 README에 불명확, README는 구형 이동 데모 설명 → 저장 시점을 설계에 명시하고 README를 실제 타이틀/메뉴 흐름에 맞게 정정.
5. PC/Web 공통 UI 원칙에도 불구하고 전체화면 토글은 웹에서 비활성화 → 하나의 토글/코드 경로로 변경. 웹 브라우저의 직접 클릭 또는 키 입력에 의해서만 전체화면을 요청하도록 시작 시 자동 적용은 방지. 실제 브라우저에서의 성공 여부는 미검증.
6. `AGENTS.md`에 구현 후 설계 대조 및 수정 루프 의무가 없음 → D절에 대조·수정·검사·재대조 및 보고 기준 추가.

### 2차 대조 — 정적 재검사
- 화면/스크립트 리소스 존재 및 상대 경로 일치
- 타이틀 자동 진입, 이어하기 표시·활성 조건, 진행 저장·복구, 재시작 시 삭제
- ESC·일시정지·설정·패배 연결 및 임시 F9 부재
- PC·웹 공통 종료/전체화면 UI, 글꼴·색상·이미지/음악 연결점
- `AGENTS.md` 검증 루프와 README/설계의 일관성

**완료 조건:** 위 항목을 다시 대조하여 확인 가능한 불일치가 없고 정적 참조 검사가 통과해야 한다. GitHub Actions의 헤드리스 씬 검사/Web 내보내기는 `devel` 반영 시 별도로 확인한다. 실제 브라우저에서 클릭·저장·전체화면·종료를 검증한 것으로 표시하지 않는다.

## 3. 검증 불가 또는 후속 작업

- 웹 브라우저의 `user://` 저장 지속성, 실제 이어하기 복구와 브라우저 새로고침
- 일시정지 및 설정의 실제 포커스·ESC 입력 상호작용
- 웹 전체화면의 사용자 입력 기반 전환 및 취소(브라우저 보안·브라우저별 차이)
- 실제 패배 판정·전투 진행(아직 미구현, 임시 F9 없음)
- 한글 렌더링의 눈으로 확인하는 화면 QA
- 실제 새 아트/음악 에셋의 삽입 및 표현(아직 자산 미등록)

검증 불가능한 항목을 임의로 정상 처리하지 않으며, 추가 요구를 확정하지 않은 상태에서 기능을 늘리지 않는다.
